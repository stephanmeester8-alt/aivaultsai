2. API-key & security (actie vereist)

  • Correcte key-aanmaak op https://platform.deepseek.com (API Keys); geen OpenAI/Gemini-key. €2 tegoed was voldoende voor tests.
  • Een volledige DeepSeek API-key is tijdens het plakken van een trajectory in de chat terechtgekomen → behandelen als gecompromitteerd: revoke op platform.deepseek.com, nieuwe key aanmaken, instellen via Settings → Models → DeepSeek, testzin: "DeepSeek Harness API connection is working." Key nooit in chat/logs plaatsen.
  • Security-observatie: de agent kon C:\Users\Startklaar\.dsh\.credentials.yaml lokaliseren en lezen — de read-tool kan secrets aan het model blootstellen (boundary: credential file → filesystem tool → model context).
  • Empirische sandbox-test: write buiten de workspace geblokkeerd onder workspace-write (svgWriteError: file access denied); geen escalatie, bestand niet aangemaakt → boundary werkt.

3. Architectuur-inzichten

  • Agent = Model + Harness; "Everything is a plugin" op basis van Cordis (plugin/microkernel-framework); profielen/modi zijn plugin-composities (web, headless, tui; eigen profiel samen te stellen via --patch).
  • Package-splitsing: dsh-agent (interface, geen loop), dsh-agent-loop (executieloop), dsh-tools (tool call → pre-execute → guards → execute → post-execute → finalize → result), dsh-session, dsh-subagent, dsh-skill, dsh-host-*, dsh-llm, dsh-credentials-local.
  • Harness beïnvloedt prestaties (StateM-studie): DeepSeek-V4 Flash 82,7% → 88,1% door betere runtime/state/runbooks zonder modelwijziging.

4. Praktijktests

  • Debug-lab: 11/11 tests; harness lokaliseerde en fixte een bug in src/string-utils.ts (+ testcorrectie wordCount); trajectory toonde de echte agent-loop.
  • Security-boundary-test: write-denial buiten de workspace empirisch bevestigd.
  • Video-review van een eerste harness-sessie met verbeterpunten voor de werkwijze.

5. Productieplan AIVaultsAI

Kern: de harness inzetten als gecontroleerde junior/mid-level software engineer in een afgebakende workspace (lab of Git worktree), nooit direct op productie: eerst inspecteren → ontwerpen → één taak uitvoeren → testen → rapporteren.

  • Rollen: codebase analyst (read-only), coding agent, QA/debugging agent (failures groeperen per root cause, fix per root cause, regressie-analyse), code reviewer (PR-review: correctness, security, auth, error handling, races, performance, DB, contracts, typing, coverage, compatibiliteit), research/intelligence.
  • Takenlijst: T1 beveiliging/permissions · T2 SEO/GEO-agent · T3 commerciële intelligence · T4 prospect discovery & qualification · T5 outreach/e-mail · T6 learning/feedback loop.
  • Prompt-kernregels: alleen huidige taak; read-only tenzij expliciet vereist; geen secrets/harness-config; niets buiten de workspace; geen packages installeren; evidence-based (repository = source of truth); expliciet FACT/INFERENCE/RECOMMENDATION, NOT CURRENTLY IMPLEMENTED, NOT VERIFIED; security-checklist incl. prompt injection, path traversal, unsafe subprocesses.
  • Status uit de chat: Taak 1 (architectuur-audit) compleet; Taak 2 (assistant API security: 22/22 tests, typecheck groen) compleet; Taak 3 = SEO/GEO/AEO-agentontwerp (read-only design, cyclus ANALYZE → PLAN → RECOMMEND → REQUEST APPROVAL → IMPLEMENT → TEST → MEASURE → LEARN → REPEAT), implementatie pas later.
